# 01 — APS-035 — Generate and verify approved Skill routing metadata

**Status:** ready-for-agent
**Milestone:** 6 — Known Gap Closure
**Blocked by:** None — can start immediately.
**PRD requirements:** [PRD.md](../../../PRD.md) §7.2–7.4; AC-R01, AC-R02, AC-R03, AC-R04, AC-R05.

**What to build:** A CREATE or UPDATE Skill candidate carries usable routing information through the exact Proposal and Approval into the generated Skill. The evaluator rejects incomplete metadata and any divergence from the approved payload.

## Scope and implementation boundaries

Extend the existing mother-Skill candidate/generation instructions and generated-asset evaluator. Reuse Proposal digest, exact payload comparison, candidate evidence, and filesystem-backed known-good builders. Do not introduce a second schema engine, a compatibility format, or a runtime project Apply API. This ticket concerns generated project Skills, not only mother-Skill frontmatter.

PRD.md remains the sole specification. Follow its §4–5 and §42 limits; do not add unrelated refactors or modify business source. The description must communicate both what the workflow does and when it applies, not merely a technology stack; semantic intent remains the Agent's responsibility.

## Acceptance criteria

- [ ] Every CREATE/UPDATE Skill candidate includes name, routing.description, routing.positiveIntents, routing.negativeIntents, taskTriggers, whenNotToUse, workflowSteps, and verification, backed by current evidence.
- [ ] Generated frontmatter uses the approved description and a name exactly matching its Skill directory; all five required body sections are present.
- [ ] Removing description produces evaluator FAIL (AC-R01); empty or whitespace-only description produces FAIL (AC-R02).
- [ ] A directory/name mismatch produces FAIL (AC-R03), while a conforming known-good generated Skill passes.
- [ ] Actual generated bytes exactly match the approved Proposal payload (AC-R04).
- [ ] Editing description after approval fails even if it remains nonempty and plausible; changing the Proposal without renewed approval also fails (AC-R05).
- [ ] Existing conforming candidate/artifact builders are updated to the single current contract, without legacy compatibility branches.

## Verification

Start with failing generated-Skill metadata and approval-mutation tests. Exercise both CREATE and UPDATE through existing physical proposal/final snapshots. Assert the intended evaluator failure, not merely any failure. Run the focused Skill contract and filesystem evaluator tests, then `npm test`. Leave the working tree valid and testable. No live routing success is claimed by this deterministic ticket.
